# DisCraft: устройство

> Играть в Dishonored, *будучи* игроком Minecraft: настоящая физика, инвентарь, блоки и бой
> Minecraft в настоящем мире Dishonored, со стражей, которая видит тебя, поднимает тревогу и
> дерётся.

Статус: v0.1, первая версия. Половина для Minecraft — форк работающего SkyCraft. Половина для
Dishonored написана заново и проверена сборкой (MinGW, clang, MSVC в CI) и юнит-тестами, но ещё
не в самой игре. Список «что проверить первым» в конце.

## 1. Принцип

Как и в SkyCraft: **ни одна игра не переписывается.** Minecraft считает своё (движение, коллизии,
бой, инвентарь, блоки), Dishonored своё (мир, ИИ, миссии, сохранения). Моды только переводят:

- Dishonored говорит Minecraft, *какой формы мир* и *где персонажи*;
- Minecraft говорит Dishonored, *где игрок*, *кого он ударил* и *что нарисовать поверх*.

## 2. Компоненты

```
┌──────────────── Dishonored.exe (UE3, x86, D3D9) ────────────────┐        ┌────────── javaw.exe (Minecraft 26.3 + Fabric) ──────────┐
│  d3d9.dll (Ultimate ASI Loader) ──loads──▶ DisCraft.asi          │        │  discraft (Fabric mod, fork of SkyCraft's)              │
│                                                                  │        │                                                         │
│  ue3/UE3      engine discovery + reflection (no SDK)             │        │                                                         │
│  Collision    Actor.Trace grid → mesher → tris + voxels ─────────┼──────▶ │  DisCollision → MC collision (DisTri/TriCollider)       │
│  Actors       pawns → actor table ───────────────────────────────┼──────▶ │  DishonoredActorEntity (invisible, hittable)            │
│  Input        WndProc / Raw Input / DirectInput filter ──────────┼──────▶ │  InputBridge (as if MC's window had focus)              │
│  Actors       TakeDamage hook + health buffer → kInHurt ─────────┼──────▶ │  player.hurtServer(...)                                 │
│                                                                  │        │                                                         │
│  Game         PlayerTick hook: pawn = MC feet, view = MC look ◀──┼─────── │  McState (20 Hz ticks + QPC stamps)                     │
│  Actors       TakeDamage on pawns ◀── kEvHitActor ───────────────┼─────── │  DisCombat                                              │
```

## 3. Отличия от SkyCraft

| | SkyCraft (Skyrim) | DisCraft (Dishonored) |
|---|---|---|
| Движок | Creation Engine, 64 бит, D3D11 | Unreal Engine 3, **32 бит**, **D3D9** |
| Загрузка | SKSE + CommonLibSSE-NG + Address Library | Ultimate ASI Loader + свой поиск структур движка во время работы |
| Кадр игры | `PlayerCharacter::Update` | подмена `UFunction::Func` у `PlayerController.PlayerTick` |
| Мир → коллизия | обход форм Havok (точные треугольники) | вертикальные лучи `Actor.Trace` по сетке + мешер |
| Урон по NPC | конвейер ударов Skyrim | `Pawn.TakeDamage` (скрипт UE3) |
| Рендер блоков | D3D11, шейдеры, внутри кадра до пост-обработки | D3D9 фиксированный конвейер в `Present`, глубина игры |
| Масштаб | 70 единиц = 1 блок | автоматически: рост персонажа = 1,8 блока |
| Общая память | ~196 МБ | 95 МБ (умещается в 32-битный процесс) |

Протокол тот же по раскладке. Поменялись имя (`Local\DisCraft_v1`), magic (`DISC`), размеры
больших колец и оверлея (до 2560×1600; больший экран растягивается) и имена полей (Sky → Game).

## 4. Поиск структур Unreal Engine 3 (`native/src/ue3`)

Чтобы не зависеть от конкретного `Dishonored.exe` (Steam, GOG, Epic, патчи), ничего не
захардкожено.

1. **GNames.** В записываемых секциях exe ищется `TArray {data, num, max}`, у которого запись 0
   содержит текст `None`, а среди следующих 16 есть `ByteProperty`, `IntProperty`, `BoolProperty`…
   (жёстко заданные первые имена UE3). Смещение текста в `FNameEntry` и ANSI/UTF-16 определяются
   тут же.
2. **GObjects.** Ищется `TArray`, где у каждого объекта (по выборке) есть поле, равное его
   собственному индексу. Это `UObject::Index`.
3. **UObject.** `Name` — пара FName, под которой среди всех объектов встречаются `Core`,
   `Engine`, `Actor`, `PlayerController`…; `Class` — указатель на объект, для которого
   `Core.Class` — свой же класс; `Outer` — поле, по которому `Class Engine.Actor` лежит в
   `Package Engine`.
4. **UStruct / UField / UProperty / UFunction / UEnum** находятся по известному содержимому:
   `SuperField` (`Actor` → `Object`), `Children` (первое поле с Outer = сама структура), `Next`
   (цепочка полей `Actor`; у `Vector` ровно X, Y, Z), `PropertySize` (`Vector` 12, `Plane` 16),
   `Offset`/`ElementSize`/`ArrayDim` (X/Y/Z на 0/4/8, `Location` 12 байт), `BitMask`
   (у bool-полей `Actor` разные биты в одном слове), `Func` (у всех скриптовых функций одна
   точка входа — `ProcessInternal`), `FunctionFlags` (бит `FUNC_Native` совпадает с «Func ≠
   ProcessInternal»), `UEnum::Names` (`EPhysics` начинается с `PHYS_None`).
5. Дальше обычная рефлексия: классы, поля и функции по именам (без учёта регистра, как сами
   FName).

Всё это проверено в `native/tests/UE3Test.cpp` на модели движка в двух **разных** раскладках.
Детектор обязан найти каждую точно. Любое смещение можно переопределить в `[Engine]` в
`DisCraft.ini`, а найденная раскладка пишется в лог.

**ProcessEvent** (через него вызываются `SetLocation`, `Trace`, `TakeDamage`…) — виртуальный
метод. Его слот в vtable находится при первом вызове нашего `PlayerTick`: адрес возврата лежит
внутри `ProcessEvent`, и это та запись vtable, функция которой начинается ближе всего ниже него.
Слот можно задать вручную (`iProcessEventIndex`).

**FFrame** (параметры функции, которые читает перехват `TakeDamage`) — смещение `Node` в кадре
находится при первом вызове по паре «наша UFunction, наш self».

## 5. Поток и кадр

- **DllMain** запускает init-поток. Он создаёт общую память, запускает Minecraft, ставит хуки
  D3D9 (через `IDirect3D9::CreateDevice` и временное устройство) и DirectInput (vtable устройств),
  находит окно игры и подменяет его WndProc.
- **Всё, что трогает объекты движка, происходит в игровом потоке.** Init-поток шлёт окну
  сообщение, движок между кадрами его обрабатывает, и в этот момент выполняются поиск структур и
  установка хуков. Потом каждый кадр приходит через `PlayerTick`.
- **Кадр (`Game.cpp`):** heartbeat → чтение `McState` → состояние игры (пешка, пауза, кинематограф,
  F11) → смена карты (новая эпоха коллизий) → телепорт (если игра сама переместила игрока) →
  обзор мышью (формула Minecraft) → «марионетка»: пешка ставится в интерполированные ноги
  Minecraft (`SetLocation`, `PHYS_Flying`, `bCollideWorld = false`), поворот контроллера равен
  взгляду Minecraft, высота глаз берётся из Minecraft, ввод игры отключается
  (`bIgnoreMoveInput/LookInput`) → `GameState` в общую память → снимок камеры (`PlayerCamera.
  CameraCache.POV`) для рендера → бой → трассировка мира.
- **Интерполяция.** Тики Minecraft (20 Гц, с метками QPC) интерполируются на часах Dishonored
  чуть в прошлом, без экстраполяции. Схема перенесена из SkyCraft.
- **Рендер-поток** (`Present`): дренаж кольца рендера, блоки, оверлей, строка статуса. Heartbeat
  идёт и отсюда, пока игра тикала не позже двух секунд назад (пауза не рвёт связь).

## 6. Координаты

UE3 левосторонняя, Z вверх (X вперёд/«север», Y вправо/«восток»). Minecraft правосторонняя,
Y вверх, Z на юг.

```
mc.x = ue.y / s    mc.y = ue.z / s    mc.z = -ue.x / s
mc.yaw = ue.yaw + 180°    mc.pitch = -ue.pitch       (ротатор UE: 65536 = 360°)
```

Определитель −1 — ровно смена «рукости», поэтому мир не зеркалится (это проверяют тесты).
`s` (единиц Unreal на блок) по умолчанию равен 2 × полувысоте цилиндра игрока / 1,8.

## 7. Мир для физики Minecraft (`Collision.cpp`, `Mesher.cpp`)

- Мир режется на колонны 8×8 блоков (регионы Minecraft) высотой 96 блоков вокруг уровня
  игрока.
- В каждой колонне по сетке (¼ блока рядом с игроком, ½ дальше) идут вертикальные лучи
  `Actor.Trace` вниз (находят все обращённые вверх поверхности: пол, крыши, землю) и вверх
  (потолки). Попадания в персонажей пропускаются.
- Мешер собирает из этого твёрдые интервалы колонки. Ниже самой нижней «крыши» всё твёрдое; одна
  сторона без другой даёт слой толщиной ¼ блока. Из интервалов получаются:
  - треугольники для гладкого коллайдера игрока: наклонный верх по нормали поверхности,
    плоский низ и вертикальные стенки там, где соседняя колонка открыта;
  - маски 8×8×8 на блок для остального (мобы, предметы, стрелы).
- Бюджет 4 мс на кадр, 20 мс пока Minecraft ждёт землю под ногами. Ближние колонны
  перетрассируются каждые 3–6 с (двери, движущиеся объекты), дальние раз в 30 с.

## 8. Бой (`Actors.cpp`)

- **Таблица персонажей:** `WorldInfo.PawnList` (или скан объектов), до 64 блоков, с размерами
  цилиндра, здоровьем и враждебностью (`Controller.Enemy == игрок`).
- **Удар из Minecraft:** `TakeDamage(DamageAmount = урон × fDamageToGame, EventInstigator =
  PlayerController, Momentum = отброс, DamageType, DamageCauser = пешка игрока)`. Тип урона
  подбирается по именам классов `DamageType` в игре (их список пишется в лог) или задаётся в ini.
- **Взрыв TNT/крипера:** `HurtRadius` в точке взрыва.
- **Урон по игроку** забирает Minecraft, двумя путями:
  1. перехват скриптового `TakeDamage` у пешек (только не-native функций: native читает
     параметры из байткода вызывающего, её нельзя пропустить). Для игрока вызов отменяется, урон,
     тип и атакующий уходят в Minecraft;
  2. «буфер здоровья»: пешке игрока выставляется большое здоровье, и любое уменьшение (урон,
     прошедший мимо `TakeDamage`) тоже уходит в Minecraft. Если игра ограничивает здоровье
     максимумом, буфер переходит на максимум.
- **Смерть в Minecraft:** `Pawn.Died(...)`, дальше обычная смерть и загрузка Dishonored.

## 9. Рендер (`Render.cpp`, `WorldRender.cpp`)

- Хук `Present` (и `Reset`) у устройства игры: через `IDirect3D9::CreateDevice` плюс временное
  устройство, если игра успела раньше.
- **Блоки:** секции Minecraft (меши из его же рендерера блоков: модели, тинт, AO, свет) в
  managed-буферах, атлас текстур. Фиксированный конвейер D3D9, без компилятора шейдеров.
  Проходы: непрозрачные, вырезанные (alpha test), сущности и частицы, полупрозрачные (сортировка
  по расстоянию). Камера — `POV` камеры игры (позиция, ротатор, FOV), рендер относительно камеры
  (точность float). Проекция с бесконечной дальней плоскостью, как у UE3.
- **Глубина:** режим 1 — буфер глубины игры (обычный Z), 2 — он же с обратным Z, 0 — свой буфер
  (блоки поверх всего). F10 переключает режимы в игре, ближняя плоскость задаётся в
  `fNearClipUU`.
- **Оверлей:** кадр Minecraft (рука, HUD, экраны) с premultiplied alpha. Прицел рисуется
  инвертирующим смешиванием, как в Minecraft. Виртуальный курсор показывается, когда открыт
  экран Minecraft.
- **Строка статуса:** текст через GDI в текстуру (без D3DX).

## 10. Ввод (`Input.cpp`)

- Подмена WndProc окна игры: клавиши, мышь, колесо, текст и `WM_INPUT` уходят в кольцо ввода
  Minecraft (сканкоды переводятся в SDL по таблице SkyCraft). Игра их не видит, кроме
  разрешённых клавиш (`sGameKeys`).
- Хуки `IDirectInputDevice8::GetDeviceState/GetDeviceData` (A и W): если игра читает мышь и
  клавиатуру через DirectInput, дельты мыши забираются для взгляда, а игре отдаются нули.
- Если за 2 с управления не пришло ни одной дельты мыши, DisCraft сам регистрирует Raw Input.
- Ввод не перехватывается, пока открыто меню игры, идёт кинематограф, нажат F11 или игра не
  тикала дольше 300 мс (загрузка).

## 11. Что проверить первым в игре

1. Лог: «UE3: layout …», «engine: …», «hooked …PlayerTick», «ProcessEvent is vtable slot N».
2. «puppet on». Ходьба: совпадает ли направление (yaw), правильный ли масштаб, нет ли
   проваливания (коллизия пришла: `[Debug] bDiagnostics = 1` пишет регионы).
3. Блоки: стоят ли на месте при поворотах, прячутся ли за стенами (F10).
4. Удар по стражнику: отнимается ли здоровье, реагирует ли ИИ (иначе поменять
   `sDamageTypeMelee`).
5. Удар стражника: приходит ли урон в Minecraft, не умирает ли Корво сам.
6. `G`: открываются ли двери. Если нет, нужна другая функция в `sActivateFunction` (поискать в
   логе/SDK, как Dishonored называет взаимодействие).
